Agents werden zur Plattformfrage – nicht nur zum Maker-Feature.

Die erste Ausgabe bündelt die wichtigsten Entwicklungen seit Juni: eine neue Copilot-Studio-Laufzeit, agentische Dataverse-Funktionen, konkretere Identitäts- und Governance-Bausteine sowie Lizenz- und Release-Vorbereitungen, die jetzt in Kundenprojekten relevant werden.

BestätigtPreview & RoadmapCommunity

Executive Summary

Microsoft verschiebt den Schwerpunkt sichtbar von einzelnen Copilot-Funktionen hin zu einer governbaren Agentenplattform. Für Architekturentscheidungen bedeutet das: Agentenidentität, Testbarkeit, wiederverwendbare Skills, Dataverse-Zugriffswege und Lizenznachweise gehören ab sofort in das Solution Design.

  • Copilot Studio: Die neue Agent Experience ist als „production-ready preview“ verfügbar und kombiniert eine neue Orchestrierung mit Microsoft IQ, Skills, Memory und Multi-Agent-Delegation.
  • Dataverse: MCP-, Management- und Coding-Agent-Funktionen machen Dataverse zunehmend zur programmierbaren Daten- und Tool-Schicht für Agents.
  • Governance: Entra Agent IDs, Agent Inventory und Evaluationen liefern die Bausteine für einen belastbaren Agent-Lifecycle – sind aber noch nicht überall GA.

1. Neue Agent Experience verändert das Zielbild für Copilot-Studio-Lösungen

Microsoft führt die neue Agent Experience parallel zur klassischen Oberfläche ein. Sie nutzt eine erweiterte Orchestrierungs-Laufzeit und ergänzt Microsoft IQ, wiederverwendbare Skills, persistentes Memory sowie die Delegation an spezialisierte Agents.

Was sich geändert hatAgent-Fähigkeiten werden modularer: Skills lassen sich paketieren und wiederverwenden; Memory speichert nutzerbezogenen Kontext; Microsoft IQ bindet Organisationsdaten ein.
Warum es wichtig istDas ist mehr als ein UI-Refresh. Es verändert Komponentenmodell, Datenzugriff, Teststrategie und die Frage, welche Funktionen in klassischen Agents weitergeführt oder neu gebaut werden.
Jetzt prüfenFür neue PoCs eine zweite Architekturspur auf der neuen Experience anlegen. Noch keine unkontrollierte Migration produktiver Agents: Funktionsparität, Region, Datenresidenz, Modellwahl, Exportierbarkeit und ALM-Verhalten je Use Case dokumentieren.

Quelle: Microsoft „What's new in Copilot Studio“, aktualisiert am 16. Juli 2026.

2. Agenten erhalten eigene Identitäten – Governance muss objektbezogen werden

Copilot Studio kann in der Vorschau automatisch Microsoft Entra Agent IDs erzeugen. Parallel steht ein Agent-Inventory-Schema zur Verfügung, mit dem Agents über Admin Center, API oder Azure Resource Graph inventarisiert und auditiert werden können.

Was sich geändert hatConnector-Berechtigungen, Conditional Access und DLP können perspektivisch stärker einem einzelnen Agenten statt nur Maker, Umgebung oder Verbindung zugeordnet werden.
Warum es wichtig istDas schließt eine zentrale Governance-Lücke: Bei autonomen oder geteilten Agents reicht die klassische Benutzeridentität nicht für Ownership, Least Privilege und saubere Auditierbarkeit.
Jetzt anpassenDas Governance-Framework um ein Agent-Register erweitern: Business Owner, Technical Owner, Datenquellen, Tools, Agent ID, erlaubte Identitäten, Risiko-Klasse, Evaluationsstatus, letzte Prüfung und Stilllegungsprozess.

3. Dataverse wird zur Tool- und Kontextschicht für Coding Agents und M365 Copilot

Der Release-Plan bündelt mehrere relevante Schritte: Dataverse SDK for Python für agentische Flows ist GA, verbesserte MCP-Tools und der Management MCP Server sind für Juni als GA ausgewiesen; Dataverse Skills für Coding Agents und das Chatten über Geschäftsdaten befinden sich in Preview. Verbesserte Record Descriptions für Copilot-/mention sind für Juli Preview und August GA geplant.

ArchitekturwirkungFür Agenten gibt es nicht mehr nur „Dataverse Connector oder Knowledge“. MCP, Skills, Python SDK und semantische Beschreibung bilden verschiedene Zugriffs- und Ausführungsebenen.
ALM-WirkungZusätzlich zu Solutions müssen Skill-Pakete, Agent-Konfigurationen, Berechtigungen, Prompt-/Description-Qualität und serverseitige Tools versioniert und getestet werden.
Jetzt lesen und prototypisierenFür einen bestehenden Dataverse-Use-Case eine Zugriffsmatrix erstellen: Knowledge/semantic retrieval, Connector, Custom API, MCP und SDK. Pro Option Datenumfang, Transaktionsbedarf, Identität, Auditierbarkeit, Latenz und ALM bewerten.

4. Managed-Environment-Lizenzierung ist klarer – aber weiterhin nutzungsbezogen

Microsoft listet die qualifizierenden Entitlements inzwischen konkret auf. In einem Managed Environment muss aktive Nutzung durch eine passende Standalone-Lizenz oder einen qualifizierenden Pay-as-you-go-/Kapazitätsansatz abgedeckt sein. Ein Nutzer benötigt für die Managed-Environment-Berechtigung nicht gleichzeitig Power Apps Premium und Power Automate Premium; eine passende Premium-Lizenz kann genügen. Der Developer Plan deckt die Nutzung von Assets in Managed Environments nicht ab.

Typisches Risiko„Managed Environment aktiviert“ wird als rein technischer Schalter behandelt, ohne App-, Flow- und Nutzerpopulation gegen die tatsächlichen Entitlements zu prüfen.
ProjektwirkungUmgebungsstrategie, App-Freigabe und Lizenzdesign müssen gemeinsam geplant werden – besonders bei M365-seeded Nutzung, Developer-Umgebungen und gemischten App-/Flow-Szenarien.
Jetzt prüfenPro Managed Environment eine monatliche Lizenzkontrolle etablieren: aktive Nutzer, ausgeführte Apps/Flows, Lizenztyp, per-app/per-flow-Zuweisungen, PAYG Meter und Ausnahmen. Developer-Plan-Nutzung ausdrücklich aus Produktivpfaden ausschließen.

5. 2026 Release Wave 2: Deutschland-Rollout für 25.–28. September einplanen

Microsoft weist den GA-Rollout für Deutschland aktuell für das Wochenende 25. bis 28. September 2026 aus. Release Waves sind verpflichtende Updates und können nicht verschoben werden.

Warum jetzt relevantZwischen Mitte Juli und Ende September bleibt genug Zeit, Regressionstests und Kommunikationswege vorzubereiten – aber nicht, wenn erst beim ersten produktiven Effekt reagiert wird.
Was betroffen istInsbesondere modellgesteuerte Oberflächen, Agent-/Copilot-Erlebnisse, Connector-Verhalten, Client-Komponenten und automatisch aktivierte Funktionen sollten in Testumgebungen beobachtet werden.
Jetzt terminierenEnde August: Feature-Sichtung und Testfall-Freeze. Anfang September: Regression in ausgewählten Testumgebungen. 25.–28. September: Change-Fenster und erhöhte Überwachung. Danach: Abnahme und Aktualisierung der Betriebsdokumentation.

6. Outlook–SAP-Integration mit Power Apps erhält offizielle Referenzarchitektur

Das Power Platform and Copilot Studio Architecture Center führt im Juli eine neue Referenzarchitektur zur Integration von Outlook und SAP mit Power Apps. Für Integrationsprojekte ist das eine nützliche Microsoft-Baseline für Verantwortungsgrenzen, Komponenten und Sicherheitsentscheidungen.

Jetzt nutzenDie Architektur gegen bestehende Integrationsstandards spiegeln: Authentifizierung, On-behalf-of-Kontext, Connector-/API-Wahl, Fehlerbehandlung, DLP-Zonen, Monitoring und Support Ownership. Nicht blind übernehmen, sondern als Review-Checkliste verwenden.
Community-FundstückPraxis

7. Community-Signal: Agent-Evaluation und UI-Tests werden Teil des normalen ALM

Power Platform Weekly hebt aus der Praxis drei Themen hervor: strukturierte Agent Evaluation in Copilot Studio, UI-Tests für Power Platform/Dynamics 365 und die bewusste Wahl zwischen Dataverse Knowledge, Connector und MCP Server.

EinordnungDas sind keine neuen Produktankündigungen, sondern ein starkes Reifegrad-Signal aus der Community: produktive Agenten brauchen messbare Qualität und automatisierte Regression.
Konsequenz„Solution import successful“ ist für agentische Lösungen kein ausreichendes Deployment-Kriterium. Es braucht fachliche Testsets, Tool-Aufruf-Tests, Berechtigungschecks und – bei kritischen Oberflächen – UI-Regression.
Jetzt pilotierenFür einen Agenten 20–30 repräsentative Testfälle definieren, erwartete Quellen/Tools und Grenzfälle festlegen und die Auswertung als Quality Gate vor Produktion dokumentieren.

Deine konkrete Aktionsliste

  • 1
    Agent-Governance ergänzen: Agent-Register und Risiko-Klassifizierung als verbindliche Artefakte definieren.
  • 2
    Neue Agent Experience testen: Einen abgegrenzten Use Case parallel auf klassischer und neuer Runtime prototypisieren.
  • 3
    Dataverse-Zugriffsmatrix erstellen: Knowledge, Connector, API, MCP und SDK nicht mehr vermischen.
  • 4
    Managed-Environment-Lizenzen auditieren: aktive Nutzung gegen Entitlements und Kapazitätszuweisungen abgleichen.
  • 5
    September-Release vorbereiten: Regression, Kommunikationsplan und Hypercare-Fenster terminieren.
